# v0.1.1 design parity

23 November 2026 · audit of every board on the portal pages **v0.1.0 · 01 … 11** (Paper file "portal v0.1.0") against branch `slice-0.1.1/logging-contract`. For each screen the target is the newest board: a v0.1.1 board replaces the v0.1.0 board of the same number. This file records what differs and what was done about it, so the design changes made in Paper without notes are now written down.

Method: each board was screenshotted from Paper and compared with screenshots of the app (headless Chromium, 1440×900, dark, sample-api and sample-worker streaming, auth off) and with the code. Times, names and counts in boards are mock data; matching means the same structure, components, copy, controls, order, tokens and spacing. Rows marked *needs server work* depend on redaction before storage (plan slice 2) or other server data that doesn't exist yet. Screens that couldn't be reproduced locally (auth, Docker disconnect, first connection) were compared from code.

## Decisions taken where boards disagree

- **Unknown flow id:** v0.1.1-04.5 (flow layout, "No events with this ID") replaces v0.1.0-08.6's full-page 404 for both "close matches" and "no matches".
- **Stream preview Diagram button:** kept; v0.1.1-04.11 still shows it (03.5 omits it).
- **Field-card email/phone:** Context (04.15), not Identity (04.1).
- **Source grouping:** stack grouping kept (v0.1.0-06.7 … 06.12: Compose project / Swarm stack, pushes under Ingest); 06.1's other changes adopted (subtitle, CORRELATION / LOG ERRORS, erroring = ingest failure, ingest-failure banner, peak ingest). "Group by host" stays as a secondary option in the select.
- **Live rate unit:** events: `events/s` in the Live pill, palette and Sources (05.4 wording), with `match/s` after it when filters are on.
- **Attempt numbering:** 03.4 / Ids & flows show attempts from 0 (BullMQ attemptsMade); event examples number from 1. The app shows the queue's own number.


## Pages 01-02

The app differs from the designs on 12 of 13 boards; only the session-expired dialog is close. The biggest gap is the first-logs success screen (02.4): the board has a whole "You're live." page, and the app only shows a banner inside the connect panel.

**How each board was checked:**
- **All 13 boards are v0.1.0.** Neither page has any v0.1.1 board.
- **Read from code only:** `/setup`, `/signin`, valid invite acceptance, invite expired (01.1–01.4) and the session-expired dialog (01.5). With auth off, `/setup` and `/signin` redirect to the stream, and invite/reset need real tokens. The code is in `web/src/routes/auth.tsx`, `components/auth/*`, `components/session-expired.tsx` and `lib/use-stream.ts`.
- **Welcome (02.1), from code only.** It only renders when there are zero sources (`stream.tsx:467`), and sample sources are streaming.
- **First logs (02.4), from code only.** It needs a source to connect for the first time.
- **Vector, Fluent Bit, OpenTelemetry and File (02.5–02.8), screenshot plus code.** I screenshotted them before a token is generated. I did not click "Generate token", because that would create real ingest tokens on the server. The after-token state comes from `routes/connect.tsx` and `lib/connect.ts`.
- **Wrong URL values in the brief.** The app's values are `?kind=fluentbit` and `?kind=file`. `?kind=fluent` and `?kind=pipe` silently fall back to Docker.
