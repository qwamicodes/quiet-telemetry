# Changelog

## 0.1.1 (unreleased)

Canonical completion events, safe request/response context and retained history. Scope and slices: `docs/v0.1.1-plan.md`.

- **Logging contract.** The copyable prompt now asks for one canonical completion event per request, job attempt or run: one UTC `timestamp`, `level` (error for a recorded error or HTTP ≥400, warn for a slow success, info otherwise), `service` · `env` · `version`, a business `flow`, `method` · `path` · `status_code` · `duration_ms`, `request` / `response` (approved headers, params, query, opt-in bodies with `body_capture: disabled | truncated`), typed `error` objects and business fields set directly on the event. Credentials become `[REDACTED]`; email and phone stay visible unless a source rule hides them. No `outcome`, `msg`, `wideEvents` or calls list. Jobs keep the queue's own id (`payout-88-1300`) with `queue` and attempt number. Sampling keeps errors, HTTP ≥400, slow successes, failed attempts and confirmed recovery; the routine rate defaults to 100%. Stack notes: Node · pino, TypeScript · Elysia, Python · ASGI, Go · net/http, Rust · Axum and Detect from codebase. Records in the v0.1.0 format keep working everywhere.
- **Check my logs, v0.1.1 checks.** JSON lines, one timestamp, level, deployment context, one completion event per request (reads `status_code`, and `status` from older records), request_id, job_id, scoped job identity (id + queue + service), parent request_id on jobs, duration_ms · native attempt, typed error fields (stringified JSON in `error.message` fails), completion evidence, request/response capture and a sensitive-value scan for unredacted credentials (auth headers, tokens, cookies, JWTs, private keys; email and phone are no longer flagged). Two new statuses: `review` when the sample can't settle a check (standalone jobs, missing completions, a clean secret scan, which is never a privacy guarantee) and `optional` for opt-in context. The `msg`, `calls` and `pii` checks are gone. Only pass / warn / fail count toward "N / M checks pass".

- **Redaction before storage.** Every line is sanitized after parsing and before it is stored, indexed, streamed or exported, so the stream, search, Copy, Raw and exports all show `[REDACTED]` where a credential was. Values under credential keys (`password`, `authorization`, `cookie`, `api_key`, `*_token`, `*_secret` …) and credential-shaped values anywhere (`Bearer …` / `Basic …`, JWTs, PEM private keys, also inside free text and `key=value` pairs) are replaced. A source can add its own keys (`iban`, `customer.address`) and hide email or phone, which otherwise stay visible. Redacted lines carry a `redacted:N` flag. Already-stored lines are not rewritten, and there is no reveal switch.
- **Server data for the remaining screens.**
  - **Check my logs:** each check that misses shows a few failing records: a note (`missing request_id`, `error is a string`) and an excerpt that is redacted again before it leaves the server. Verify your logs lists them under Failing fields.
  - **Docker:** the engine version and socket path show on setup, Connect and About ("/var/run/docker.sock · engine 27.3"). While Docker is unreachable, the stream says "reconnecting in 4s (attempt 3)".
  - **Level scheme:** a source's sample reports pino numbers, names or none, so "You're live." can say "pino levels ✓".
  - **Dropped records:** lines that ingest drops or cuts are counted per minute by reason (text policy, parse limit, size limit, duplicate key) with their size; the payloads are never kept. Sources → Rejected shows "Dropped 24h" and the list. JSON nested past the parser limit is now flagged `parse_limit`.
  - **⌘K:** source rows add the id key their rows show (`docker · 1/s · job_id`).
- **Old-format sources (v0.1.1-00.3).** A source whose recent records still use the v0.1.0 shape (`outcome`, `wideEvents.calls`, `msg` without `flow`, `status` without `status_code`) shows `· v0.1.0` in the sidebar until 24 hours after its last old record. Its upgrade screen (`/sources/<name>/upgrade`) maps what the code writes to what v0.1.1 expects with counts from the newest 5,000 records, gives a changes-only prompt for your agent, and charts the rollout per hour after you deploy.
- **What's new (v0.1.1-00.1, 00.2, 00.4).** Accounts from before the upgrade see a dot on the version chip, `new` / `updated` markers on the screens and Guide tabs that changed (rolled up to the sidebar), and a one-time banner. The What's new sheet lists changes to your logs, sources still on the old format, and changes to quiet, with Mark all as seen. Markers clear as you open each screen; seen state is kept per account.

The result keeps the status and adds why: `verify_signature → 401 · invalid_signature`, `create_order → 201 · order 1181`, `list_payouts → 200 · slow`, `settle_dealer_payout → upstream_timeout · attempt 2 · final`. A 4xx reads as an error; a slow success keeps its green status with an amber `slow`. `flow` is the name the row shows first; older `operation` / `event` / `msg` names still work. - **Retained history, part 1: storage and connectors.** Optional and off until you connect storage; the local SQLite window works exactly as before. Settings → Storage → Retained history connects **Garage** (in-house; `make up-history` starts it and quiet sets it up as `garage-local`), **Cloudflare R2**, **Amazon S3** or any **S3-compatible** store, with **Verify** reporting write / read / list / delete. Hours that leave the local window are archived there as compressed SQLite segments (with a manifest and checksum) before they are dropped. When the destination is unreachable the hours wait on local disk with a banner and backoff; hours lost anyway (disk cap, no destination, excluded sources) are recorded as gaps. Secrets are encrypted at rest and never shown again. A source can be left out with *Keep in retained history*. Searching retained history comes next.
- **Retained history, part 2: retention policy.** Settings → Storage → Retained history sets how long history is kept (30 days by default; 7, 90 or 365 days, a custom number of days, or indefinitely) for every destination; a shorter window first says what it deletes ("deletes 214 hours · 38 GB from …") and asks. A destination can have a capacity (or uses its Garage bucket quota); when full, quiet evicts the oldest hours or stops archiving, as you choose. Deletes a bucket refuses (AccessDenied, object lock) show as **cleanup blocked** with a banner, backoff and Retry instead of retrying in a loop. After turning history on, **Archive now** backfills the hours still in the local window. Making another destination active can **copy history** across, and removing a destination can **delete its history** first. Backfill, copy and delete run as background jobs with progress, Cancel and Retry, and resume after a restart. **Turn off** stops archiving and keeps what is archived.
- **Retained history, part 3: search across locations.** When a search range you choose reaches past the local window, Search shows what retained history covers (per destination, with gaps and where history starts: "No retained history before 09 Nov") and searches it: at once for a few hours back, on **Search retained history** for longer ranges. Archived hours are downloaded into a local cache (`--history-cache`, 2 GB by default, checksum-verified, least recently used first out) and searched with the same engine as the local window; matches join the results with a location tag, the histogram greys out what wasn't searched, and a search can be cancelled (partial results stay) or come back incomplete when a destination is unreachable ("garage-local not searched · 09–21 Nov"). Results export like any search. A flow that may continue in retained history says **Related history unavailable** and can load it into its activity list.
- **Storage screens match the v1.1 designs.** Settings → Storage is now Overview · Connectors · Policy. Connectors are tested (list, write, read, delete) before they are saved, Amazon S3 can use the host's AWS credentials or temporary credentials with a session token, and every storage state (copying the local window after activation, unreachable, at the size limit, cleanup blocked) has its own screen. History retention defaults to 30 days with one size limit per connector, activating a connector copies the recent local window to it, and removing one leaves its objects in the bucket. Search and Flow show retained history as coverage, retrieval per location, and incomplete, cancelled or out-of-range states.
- **Redaction screens.** Sources → a source → Settings → **Redact sensitive data**: credentials and auth headers are always removed; add custom keys or field paths, and choose whether email and phone are redacted before storage (existing records are unchanged). **Redaction preview** runs the unsaved policy over a sample event and shows the sanitized JSON with what was removed (`POST /api/sources/:name/redaction-preview`). The field card's tab aside shows redactions, truncation, keys or bytes; collapsed groups count their redacted values; Raw says it is the sanitized record and copies a "sanitized line"; the truncated-body note names the 8 KB capture limit. Export dialogs say exports hold sanitized stored events and show "Redaction always applied". Owners now export what is stored; members' exports still mask personal data ("Mask in members' exports" per source).
- **Logging setup tab** per source: runtime, queue, SLOs & sampling, request/response capture and the source's sensitive-data rules. It fills the Guide's agent prompt; Continue in guide opens it for that source.
- **What's new matches the v0.1.1 boards (00.1–00.4).** A banner on the Guide overview; a 560px sheet listing the nine changes (fields, marker column, old-format callout, Full changelog); outlined `updated` and filled `new` markers; the full version with a round dot on the chip. The upgrade screen for a v0.1.0 source sits inside the Guide: source select, Re-check, what your code writes against what v0.1.1 expects, a changes-only agent prompt and "After you deploy" progress.
- **Flow, search and mute details.** Flows with child jobs say "native queue links · children progress independently", list the request first with child jobs folded, and read timings as `350 ms`; the Diagram tab uses the board's icon and a single-event diagram keeps `1 / 1` and ×. Search loads further pages with "Show more flows" / "Show N more events" instead of on scroll, and a search that includes muted events shows its link with a copy button. Add global rule shows "on N of M sources", sources that already mute the rule (with "Also remove") and what is newly hidden; editing a global rule opens a side panel with the before/after count and hits by source; a source rule edits in place with its live change. Dark `--chart-1/2/5`, `--sidebar-accent-foreground` and `--syntax-string` equal the design.
- **Retained history, finishing the v1.1 boards.** A flow whose events exist only in retained history opens from search (`/api/flow?…&at=` reads the archived hours around the event), with where it came from and the way back (v1.1-23). The time-range menu shows the available history and offers the last 30 days (`GET /api/search/timeline`, v1.1-22). ## 0.1.0 (2026-11-23)

The first version: one host, one binary, a calm live view of canonical logs.

- **Ingest.** Docker containers from the local socket (named by swarm service → compose service → container, replicas merged; finds Docker Desktop, OrbStack, Colima, rootless sockets and the current `docker context`). HTTP pushes from Vector, Fluent Bit, OTLP/HTTP logs + traces, NDJSON/curl and `quiet pipe`, with send-only `qi_` ingest tokens, body and rate limits.
- **Stream.** One source at a time over a WebSocket, newest at the bottom (or top), level toggles and text filter, keyboard navigation, field card, reconnect with backoff.
- **Storage.** SQLite (WAL) hourly partitions with FTS5 and an index of every correlation id; 24h window by default (1h–7d), a disk cap that drops the oldest hour first, purge, per-source windows.
- **Flows.** Every line sharing an id, stitched across sources (request → job → retries, two hops, bounded), OTLP span trees, step graph + timeline, child steps from `wideEvents`.
- **Search & export.** Words, phrases, `level:`, `source:`, `id:`, `key:value` filters, histogram, group by flow; NDJSON / JSON / CSV export with PII masking and a 15-minute read-only `qx_` Copy-curl token; very large exports are prepared on the server with progress, Cancel and an "Export ready" toast.
- **Accounts.** First-run owner, members via copy-link invites, argon2id passwords, cookie sessions with CSRF, reset links and `quiet admin reset-password`.
- **Settings.** General (instance name, timezone, stream direction), Flow id order (keys, order, match by key or value), Storage (usage, partitions, volume by source, projection, window, cap, purge), per-source settings (display name, hide, pause ingest, window, id keys, default level, PII masking, muted lines, purge, remove that also revokes its bound tokens with Undo) with a Rejected tab; UI values override the CLI/env defaults.
- **Muted lines in search.** Hidden from Search by default; "Include muted lines in search" per source (inherit / on / off) and in Settings → General (default off, `QUIET_SEARCH_INCLUDE_MUTED`) shows them dimmed with a `muted` tag ("N muted lines included · Hide"). Show muted / Hide is a one-off `muted=include|hide` URL override; the stream still always hides them; exports from search follow the search's muted state (`/api/export?muted=auto|hide`).
- **Mute from the stream, two mute scopes.** Hovering (or J/K-focusing) a stream row shows a toolbar: **Mute** (split button) · Copy line · Open flow. Mute hides the line's route on its source in one click: the route is the first of `route`, `path`, `http.route`, `req.url`, `url`, with scheme, host, `?query` and `#hash` dropped (no route → "Mute message", the exact message). The caret (or `⇧M`) opens a menu with a **This source / All sources** switch (Tab) and three options with live 24h counts: route any method, `GET /route` only, this exact message (warns when an option matches more than ~30% of a source); the preview shows the method split, `?query ignored` and sample lines, or hits per source for a global rule. Matching rows fade out, and a toast says what went with **Undo** (`⌘Z` while it's up) and Edit rules / Global rules. `M` mutes with the default option on this source, `C` copies the line. Rows seen with Show muted are dimmed with a `muted` tag naming the rule and offer Unmute; a row hidden by a global rule offers "Show on <source> only" (Don't apply here), "Unmute everywhere" or "Open global rule"; a line matching a global rule switched off here offers "Turn the global rule back on here". Rules now have a shape (route · method + route · exact message · field = value glob; old `field:value` / text rules keep matching exactly as before and get ids on first start), an id, an on/off switch (paused rules keep their history and show "would hide N"), who / when, and how they were added (from hover / manual). **Global rules** live in the new **Settings → Muted lines** (table with 24h hidden counts, rule detail with hits by source and where it's switched off, add / edit with a live preview and "N sources already mute it · Also remove the source rules", delete for all sources with a confirm and Undo); every source, including new ones, gets them, and each source can switch one off for itself ("Don't apply here"). A line is hidden when any enabled rule that applies matches (global ∪ source). **Sources → Edit** is now a 520px sheet with tabs General · Flow id order · Muted lines: this source's rules (inline edit, pause, delete with Undo; a rule hiding 1,000+ lines a day asks first), the global rules with an "apply here" switch, a warning when a new rule is already covered by a global one, and the per-source Include muted lines in search (Inherit / On / Off). The instance **Include muted lines in search** default moved from General to Settings → Muted lines (General keeps a link; same `QUIET_SEARCH_INCLUDE_MUTED` flag). Members see everything read-only ("Only owners can edit muted lines"). Server: `/api/mute/rules` (POST / PATCH / DELETE, restore by id for Undo), `/api/mute/sources/:name/global/:id`, `/api/mute/search`, `/api/mute/stats` (24h hits per rule and source) and `/api/mute/preview` (bounded newest-first scan, scaled and marked `~` when a source has more lines than were read; stats cached for a minute); exports with `muted=hide|auto` follow the same union.
- **System.** `/api/system` and app banners for Docker unavailable, disk near/at the cap, a nearly full data volume, store write errors and refused ingest requests. In-memory live lines are capped by a shared memory budget (`QUIET_RING_MEMORY`, 64MB).
- **Click-to-copy values.** In the field card's Fields tab, a value underlines on hover and copies on click (or Enter/Space): strings unquoted, numbers/bools as text, objects and arrays as JSON, always the full value, with a "Copied <key>" toast. Clicking elsewhere on the row still picks the field for Filter by value.
- **Diagram tab.** The field card gets a 4th tab, Fields · JSON · Raw · Diagram: the line's objects and arrays as cards of typed `key: value` rows laid out left → right (or top → down) on a dotted canvas with pan and zoom. The card grows over the flow column (header stays); another tab or `Esc` shrinks it back, Full screen hides the sidebar. Click a value to copy; hover or right-click for Copy value, Copy path, Filter by value, Exclude value, Highlight this value (marks the same value elsewhere) and Use as a flow id… (stages the key in Settings → Flow id order). `−`/`+` handles fold branches; `/` searches keys and values (`2 / 5`, opens folded branches with a match, dims the rest). Large lines: past depth 3 starts collapsed, arrays show 5 items ("+ 9 more · showing 5 of 14"), and over ~200 keys / 32 KB a notice with Expand all and a minimap appears. Toolbar: fit, full screen, zoom, Export image (PNG), search, copy JSON, settings (direction, collapse depth, array cap, wrap, remember collapsed; saved in this browser). Plain-text lines keep JSON and Diagram visible but disabled with a tooltip. Stream's row preview gets a Diagram button (`D`). Lazy-loaded as its own chunk.
- **Custom source groups.** Owners make their own groups from Sources (New group, with an optional checklist of sources), move a source in from its ⋯ menu (Move to group › a group, New group…, or Automatic to reset it), and rename, reorder (Move up / down) or delete a group from its header ⋯ menu. A group you assign wins over automatic grouping (`quiet.group` → Compose project → Swarm stack → Standalone) and custom groups sit above the automatic ones in Auto and Label modes, on Sources, the sidebar, the stream source picker and ⌘K. Deleting a group sends its sources back to automatic grouping and never deletes lines. Mode Off keeps the groups and shows one flat list; they come back when grouping is on. `QUIET_GROUP_BY` locks the mode only. Saved server-side (`/api/source-groups`); members see the groups but can't edit them. Sources also gets a Custom group filter, a rules hint and an "N moved to …" note on the automatic group; Settings → General shows the custom group count.
- **No empty-state flash while filters load.** Changing a stream filter (level chips, text, `key:value` chips) keeps the previous rows dimmed with an "Updating…" spinner until the new filter's backlog arrives, or shows skeletons when there were none; "No lines match" appears only once the server has answered with zero lines. Frames from the previous filter's socket are dropped, and the "N of M lines match" counts wait for the new filter's numbers. Search keeps the previous results dimmed while a new query runs (skeletons if the previous query was empty). Sources shows skeletons while the list loads instead of "Nothing connected yet", and the Erroring tab says "Checking error rates…" until every source is counted instead of "No sources match"; a source's page says "Loading…" instead of "No line from … yet" while sources load.
- **One source per Docker container.** Sources used to be keyed by the bare Compose/Swarm service name, so same-named services in different projects (every `postgres`, `redis`, `api`, prod and staging) merged into one source under whichever project came first, and the others looked missing. Now each container is its own source (`<project>.<service>`, the Swarm service plus its replica slot, or the container name), shown by its service name with ` · <project>` added only when names collide. On upgrade, an old source with one container carries on unchanged; a merged one keeps its lines until they age out and hands its settings and custom group to each source it splits into.
- **Container restarts read only the new run.** Following a container on a Docker `start` event used to ask for its whole log (`tail=all`), so a container restarting under its restart policy (same id, json-file log kept) re-ingested its entire history on every restart: a crash loop flooded the store with millions of duplicate lines, retention churned and the source's live lines fell behind. A start now reads from the event's time (minus 1s slack) with a 1000-line safety cap; a fresh container still gets everything from its start, and attaching to already-running containers keeps its 200-line tail. quiet never asks Docker for `tail=all`.
- **Resizable sidebar.** Drag the sidebar's right edge between 200 and 420 px (default 248): the handle shows a 2px accent line and grip on hover, drag and focus, with a `264 px · default 248` tooltip while dragging (`max` / `min` at the ends). Between 140 and 200 it holds at 200; released below 140 it hides (hatched ghost, "Release to hide · back past 140 cancels · ⌘B reopens"), Esc cancels a drag, double-click resets to 248. A top-bar button (or a corner button on screens without one) and ⌘B / Ctrl+B anywhere show it again at the last width. The handle is a keyboard separator: ←/→ 16 px, Shift 64 px, Home/End min/max, Enter hides. Width and hidden state are saved per browser (`quiet.sidebar.width`, `quiet.sidebar.hidden`, clamped on load); the main column keeps at least 720 px, so the sidebar shrinks first on narrow windows; below 768 px there is no handle. Cut-off source names show the full name, group, rate and status on hover. Resizing runs once per frame on a CSS variable, so the stream keeps its scroll position.
- **JSON sent as a string.** A field whose string value holds JSON (`"payload": "{\"user\":{…}}"`, also double-encoded `"\"{…}\""`) shows as the structure it holds: nested dotted rows in Fields (`payload.user.id`, marked with a `{}` badge, "Parsed from the JSON string in payload"), pretty JSON in the JSON tab, cards marked "from string" in Diagram (the parent row tagged `json str`), and the structure in the stream's row preview. "N string values parsed as JSON · Show as sent" toggles back to the strings exactly as sent. Plain text, invalid JSON and primitives show as before; strings over 256 KB, deeper than 32 levels or past 200 per line are left as strings, and parses are memoized. Nested values copy on click like any field; since search filters only see real fields, Filter on a value from inside a string searches the line text for it ("Search for payload.user.id"). On ingest, correlation ids (`request_id`, `job_id`, `trace_id`, `correlation_id`) and custom dotted flow-id keys are also found inside string fields that hold a JSON object (≤ 64 KB), so such lines join their flows; stored fields stay as sent.
- **Click the histogram to jump.** On the stream, each minute bar with lines is a button (pointer, hover highlight, tooltip "· click to jump"; focusable, Enter/Space): clicking it pauses the stream, loads that minute from history when the live buffer no longer holds it (same source, level chips and query; muted lines stay hidden), scrolls the table so the minute's first line is at the top (newest-on-top: the minute's newest line), tints the minute's lines for a moment and marks the bar. Jump to latest / `G` / the pause toggle returns to live and drops the history rows. On Search, clicking a bar scrolls the results to that time when they're loaded; otherwise the results are re-anchored there with `at=` in the URL (newest first: lines at or before it; oldest first: at or after it), so the view is linkable, while the histogram and total still cover the whole range; a "from 14:05 back" chip clears it.
